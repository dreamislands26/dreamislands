B15. Partner Cabinet — Product Flow
Партнёр платит за три связанные функции:
Build → Distribute → Optimize

1. BUILD — создать стандартизированный wellness product
Партнёр заводит свой базовый inventory:
Rooms / Accommodation
Treatments
Practitioners / Masters
Activities / Classes
Assessments / Diagnostics
Meals / Nutrition
Transfers
Facilities
Other Services
Из этого inventory он собирает Program / Journey.
Но не произвольный hotel package. Dream Islands задаёт wellness standard:
Guest Goal → Cohort → Suitable Guest Profile → Duration → Accommodation → Activities → Treatments → Practitioners → Assessments → Inclusions → Expected Outcome → Price

Например, один и тот же inventory property может быть собран в разные продукты:
5D Reset
7D Reset
10D Recovery
Performance Week
Sleep Program
При этом treatments, rooms, practitioners и activities переиспользуются, а не вводятся заново для каждого package.
2. STANDARDIZE — пройти Dream Islands standard
Cabinet проверяет completeness и соответствие wellness-продукта стандарту DI:
Goal defined?
Target guest defined?
Cohort assigned?
Program structure complete?
Practitioners verified?
Activities/treatments structured?
Outcome measurement defined?
Commercial terms complete?
Bookable inventory available?
Результат:
Draft → Standardization Check → DI Verified → Live

То есть property платит в том числе за возможность получить DIT-standardized wellness product, который можно нормально дистрибутировать, сравнивать, измерять и рекомендовать.
Это важная B2B value proposition сама по себе.
3. DISTRIBUTE — управлять продуктом как OTA inventory
После стандартизации программа становится distribution object:
Program → Rate Plan → Availability → Restrictions → Promotions → Booking

Property управляет:
Price
Availability
Dates
Capacity
Room options
Program duration
Rate plans
Cancellation terms
Inclusions / Extras
Promotions
При изменении underlying inventory система понимает, какие wellness products это затрагивает.
Например:
Practitioner unavailable → affected programs flagged.

Treatment capacity increased → additional program inventory can open.

Room category sold out → relevant rate plans close.

4. OPTIMIZE — понять, что менять
После запуска cabinet показывает не просто hotel analytics, а performance созданных wellness products.
Demand
Views / Leads → Bookings → CVR
Economics
GMV | DI Revenue Generated | Avg Booking | Room Nights | Extras
Guest
ICP | Cohort | Goal
Product
Program | Duration | Activities | Treatments | Practitioner
Quality / Outcome
Satisfaction | Outcome | Repeat
Отсюда property принимает решения:
какой program оставить / изменить / создать;

какую комбинацию inventory использовать;

какой duration и price работают;

какие treatments добавить в package;

какого practitioner использовать;

под какой ICP/cohort создать следующий product;

какой product продвигать сильнее.

V1 — за что должны заплатить первые 10 properties
Я бы теперь сократил V1 до трёх модулей.
1. Wellness Product Builder
Inventory → Standardized Wellness Journey

Создание reusable inventory и сборка из него programs.
Это центральный differentiator от обычного OTA extranet.
2. Distribution Manager
Program → Price → Availability → Booking

Минимально необходимая OTA-функциональность, чтобы созданный product реально продавался через DI.
3. Program Intelligence
Demand → Revenue → Guest → Outcome → Recommendation

Property видит performance программы и получает конкретное решение:
Promote / Change / Extend / Bundle / Add Upsell / Create New Program
Closed Loop
В итоге B15 — это не Partner Analytics Dashboard.
Это:
Property Inventory → Build Program → DI Standardize → Publish → Sell → Measure Guest & Outcome → Improve Program → Create Next Program

Именно за этот closed loop я бы пытался получить первые 10 Paying Properties.
Тогда Dream Islands на B2B стороне становится не просто каналом, который привёл booking, а wellness product infrastructure: помогает property превратить существующий inventory в стандартизированный wellness product, вывести его в distribution и затем улучшать на основании реальных guest, commercial и outcome data.
