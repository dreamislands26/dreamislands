## Как обновлять дальше

Сайт — статический (быстрый, без зависимости от Supabase в runtime). Когда меняешь данные в Supabase (цены, тексты, новые отзывы) — НЕ редактируешь HTML руками. Делаешь так:

```bash
node build_from_supabase.js
```

Скрипт лежит в корне проекта. Тянет `programs`, `program_variants`, `faq`, `reviews` через REST API Supabase и генерирует:

- `build/programs.html` — фрагмент для `<div class="programs__grid">`
- `build/faq.html` — фрагмент для `<div class="faq__list">`
- `build/reviews.html` — фрагмент для `<div class="reviews-grid">`
- `build/data.json` — полный дамп, для проверки перед вставкой

**Важно:** скрипт нужно запускать НЕ в Claude-сборке (там нет доступа к домену Supabase), а у себя локально или на VPS — там, где будет жить сайт. Зависимостей нет, чистый `fetch`, только Node.js 18+.

После запуска — открываешь `build/*.html`, копируешь содержимое в соответствующее место в `index.html` / `faq/index.html` / `otzyvy/index.html`, заливаешь на сервер.

## Когда переходить на live-fetch (без пересборки)

Если правки в Supabase станут частыми (несколько раз в день) — имеет смысл заменить статические карточки на client-side JS, который тянет `/rest/v1/programs` прямо в браузере при загрузке страницы. Для этого:

1. RLS на `programs`, `program_variants`, `faq`, `reviews` уже разрешает анонимное чтение опубликованных строк — ничего менять не нужно
2. Подключить `anon` key в `js/main.js` (он публичный, безопасно хранить в клиентском коде)
3. Заменить статические `<article class="prog-card">` на JS-рендер из ответа API

Build-time подход (текущий) предпочтительнее для сайта с редкими обновлениями — он быстрее грузится и не зависит от доступности Supabase для посетителя.
